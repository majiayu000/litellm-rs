# Local compatible non-chat protocol audit — 2026-10-03

Issue #1409, F11 bounded batch. Baseline `ceff7f39bd2902ce7a1d1ff816d84c7fadabfb14`. This reviews existing selectors, not arbitrary names from model price tables. No model was downloaded or run; HTTP fixtures validate our dispatch, not GPU/model performance or live server availability.

Decision: adapt the existing OpenAI-like catalog/transport. The current Rust provider already supports JSON embeddings/images, binary speech and multipart transcription/translation. The official server protocols below fit those paths. Adopting another SDK, installing model servers, adding a transport abstraction or generic capability detector is unnecessary for this bounded request. LiteLLM's Lemonade adapter confirms the local-server identity, but its old default port is not used as current server evidence.

## Validation

Local HTTP fixtures cover all nine selectors, including native root/engine URL suffixes, optional/explicit authentication, retained model/input/format fields, embeddings usage, image b64 JSON, multipart files, and binary speech. Error regressions preserve 400 and 429/Retry-After semantics. A real gateway embeddings test proves missing local price rejects before the upstream, a finite exhausted provider budget rejects before the upstream, and configured price plus actual two-token usage settles $0.20. Existing zero-budget configuration semantics mean unlimited, so the exhausted-budget fixture uses a positive insufficient limit.

Repository checks passed: fmt/check, default complete tests (7,267 library tests, 1 ignored, plus integration/doc suites), default all-target clippy, and gateway/sqlite all-target clippy and complete tests (9,634 library tests, 1 ignored, plus integration/doc suites). The catalog HTTP integration suite passed 18 tests. No paid calls, model inference or vendor-account checks were run. This batch does not finish all F11 selectors or the remaining protocol adaptations listed above.
