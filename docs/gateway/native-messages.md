# Native Anthropic Messages gateway (draft)

`POST /v1/messages` selects a configured Anthropic deployment and preserves native Messages JSON/SSE, client tools, thinking signatures, usage and error envelopes. It uses existing authentication, `api.chat` permission, model/token/endpoint restrictions, guardrails, routing, callbacks and spend recording. A key restricted to `/v1/messages` can use this endpoint without gaining access to Chat Completions.

Before generation the selected account's `/v1/messages/count_tokens` counts the structured input. Cache writes reserve the most expensive requested TTL. Web search/fetch definitions require explicit `max_uses`; newer versions also require explicit `allowed_callers: ["direct"]`, and any explicit callers on tools must use direct execution. Basic `web_search_20250305`/`web_fetch_20250910` retain their documented direct default. The reservation includes the initial count plus one full model context per allowed use, and the web-search request charges. This overestimates ordinary short tool results and can reject small budgets. The request is forwarded unchanged; actual reported usage controls settlement. Web-fetch has no additional per-fetch fee, but returned content consumes tokens.

Claude 4.6 and later preserve an explicit `inference_geo` of `global` or `us`. Omission (or null) inherits the upstream workspace default; the gateway reserves the US maximum without changing the request, then settles from JSON/SSE `usage.inference_geo`. The catalog supplies the US 1.1 multiplier for input, output and both cache TTLs; per-search charges are not multiplied. A geo-capable model missing a valid returned region is treated as incomplete billing data, never silently global. Older Claude 4.5 models retain standard pricing and may omit the usage region. Missing catalog rates, including a requested cache TTL, fail before generation.

This remains a draft pending final billing-scope and integration review. Dynamic filtering, programmatic execution, code-execution/tool-search/MCP tools, top-level hosted MCP servers and nonstandard speed return native-shaped invalid_request_error before either upstream endpoint is contacted. Runtime-billed code execution cannot be priced from request counts alone; these execution modes are outside the current bounded tool scope. The bounded web-tool change is not a claim that every native extension has a strict budget upper bound. No live provider calls have been run.

The geo calculation adapts the existing LiteLLM `provider_specific_entry` price representation, keeping rates in the catalog and usage in the shared pricing pipeline. It avoids a route-only surcharge that would disagree with callbacks. Evidence: [Anthropic data residency](https://platform.claude.com/docs/en/manage-claude/data-residency) and [LiteLLM Anthropic cost calculation](https://github.com/BerriAI/litellm/blob/a5fef4b4e68963640c3062d464509129ec8863c6/litellm/llms/anthropic/cost_calculation.py).

This change reuses the existing transport and budget pipeline.
