# Native Anthropic Messages gateway (draft)

`POST /v1/messages` selects a configured Anthropic deployment and preserves native Messages JSON/SSE, client tools, thinking signatures, usage and error envelopes. It uses existing authentication, `api.chat` permission, model/token/endpoint restrictions, guardrails, routing, callbacks and spend recording. A key restricted to `/v1/messages` can use this endpoint without gaining access to Chat Completions.

Before generation the selected account's `/v1/messages/count_tokens` counts the structured input. Cache writes reserve the most expensive requested TTL. Web search/fetch definitions require explicit `max_uses`; newer versions also require explicit `allowed_callers: ["direct"]`, and any explicit callers on tools must use direct execution. Basic `web_search_20250305`/`web_fetch_20250910` retain their documented direct default. The reservation includes the initial count plus one full model context per allowed use, and the web-search request charges. This overestimates ordinary short tool results and can reject small budgets. The request is forwarded unchanged; actual reported usage controls settlement. Web-fetch has no additional per-fetch fee, but returned content consumes tokens.

This remains a draft. Dynamic filtering, programmatic execution, code-execution/tool-search/MCP tools, top-level hosted MCP servers, nonstandard speed and non-global inference geography now return native-shaped invalid_request_error before either upstream endpoint is contacted. Runtime-billed code execution cannot be priced from `code_execution_requests` alone; these execution modes and premium speed/data-residency rates still need separate accounting. The bounded web-tool change is not a claim that every native extension has a strict budget upper bound. Omitting inference_geo still inherits the upstream workspace default, so an account whose default is US-only also remains an unresolved pricing case; this draft must not be merged until that implicit-rate path is handled. No live provider calls have been run.

This change reuses the existing transport and budget pipeline. References checked 2026-10-03: [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), [web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool), [code execution](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool). Local HTTP tests verify rejection before generation, unchanged native tool definitions and auth restrictions; they do not validate provider-side invoices.
