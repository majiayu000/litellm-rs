# Native Anthropic Messages gateway (draft)

`POST /v1/messages` selects a configured Anthropic deployment and preserves native Messages JSON/SSE, client tools, thinking signatures, usage and error envelopes. It uses existing authentication, `api.chat` permission, model/token/endpoint restrictions, guardrails, routing, callbacks and spend recording. A key restricted to `/v1/messages` can use this endpoint without gaining access to Chat Completions.

Before generation the selected account's `/v1/messages/count_tokens` counts the structured input. Cache writes reserve the most expensive requested TTL. Web search/fetch definitions require explicit `max_uses`; the reservation includes the initial count plus one full model context per allowed use, and the web-search request charges. This overestimates ordinary short tool results and can reject small budgets. The request is forwarded unchanged; actual reported usage controls settlement. Web-fetch has no additional per-fetch fee, but returned content consumes tokens.

This remains a draft. Runtime-billed code execution cannot be priced from `code_execution_requests` alone; internal execution beyond bounded search/fetch, premium speed/data-residency rates and other hosted tools still need separate accounting. The bounded web-tool change is not a claim that every native extension has a strict budget upper bound. No live provider calls have been run.

This change reuses the existing transport and budget pipeline. References checked 2026-10-03: [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing), [web search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool), [code execution](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool). Local HTTP tests verify rejection before generation, unchanged native tool definitions and auth restrictions; they do not validate provider-side invoices.
