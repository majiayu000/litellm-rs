# Product Spec

## Linked Issue

GH-1132 / #1132

complexity: medium

## 用户问题

README 推荐的本地开发示例没有加载价格数据，却配置为拒绝所有未定价模型。
示例中的自托管 vLLM 模型因此会在 provider 调用前被拒绝，形成“网关能启动但
所有请求失败”的首次使用体验。

## 目标

- 让随仓库发布的开发示例在离线、本地环境中可以服务其自托管模型。
- 保留已知模型的准确内置定价，并为示例中的无上游价格模型提供明确的零成本策略。
- 对开发示例执行与主示例相同的 schema/配置验证。
- 保持生产示例的 fail-closed 定价默认不变。

## 非目标

- 把生产配置改为允许未定价模型。
- 为自托管模型猜测供应商成本。
- 在配置加载或测试时访问网络。
- 改变 pricing service、预算结算或公开错误协议。

## Behavior Invariants

1. B-001 `config/gateway.dev.yaml.example` 必须使用 cwd-independent、离线可用的内置价格源。
2. B-002 示例中的自托管 vLLM 模型没有上游价格时不得在 provider 调用前被拒绝。
3. B-003 未定价本地模型必须使用显式 `allow_unpriced` 与 `0.0` fallback，不能依赖隐式降级或空价格源。
4. B-004 内置价格源覆盖的模型仍使用其真实价格，不得因本地 fallback 全部归零。
5. B-005 主生产示例继续使用其既有 fail-closed 定价策略；开发宽松策略不得扩散到生产默认。
6. B-006 主示例与开发示例都必须反序列化、拒绝未知字段并通过完整配置验证。
7. B-007 任何随仓库发布、启用 provider 的开发示例模型，要么能在价格源中找到，要么配置为允许未定价；禁止再次形成 100% 预调用拒绝。
8. B-008 验证过程不得依赖当前工作目录或网络。

## 验收标准

- [ ] 开发示例加载内置价格源并使用 `allow_unpriced`、`0.0` fallback。
- [ ] 测试证明开发示例中的 vLLM 模型不会因 missing price 被预调用拒绝。
- [ ] 测试证明内置价格中已知模型仍保留非 fallback 价格。
- [ ] 主示例与开发示例均通过 schema、未知字段和完整 config validate 测试。
- [ ] 测试从非仓库工作目录运行时仍能读取开发示例或使用编译期稳定路径。
- [ ] 不产生网络访问。
- [ ] `cargo fmt --check`、`cargo check`、严格 Clippy、相关测试及完整测试通过。

## 边界情况

- 内置价格源加载失败必须显式报错，不能回退为全部零价。
- 后续向开发示例添加第二个 provider/model 时，验证必须覆盖所有 enabled model。
- `0.0` fallback 只表达本地自托管示例没有供应商成本，不代表 token usage 缺失。

## 发布说明

这是开发示例修复。生产示例和生产定价默认不变；复制开发示例的用户会看到
未定价本地模型按显式零成本继续请求。
